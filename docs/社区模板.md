# 社区创作模板

2026-11-09。本阶段实现「从固定示例源码套用」的社区模板。未实现任意机制模块的依赖、冲突自动解算，也不代表所有参数组合都经过玩法验收。

## 页面与使用方式

- 导航栏「社区模板」进入 `/templates`，支持搜索、官方示例、用户发布和我的模板筛选、分页。
- 工作台「发布创作模板」绑定当前选中的预览版本。填写标题、介绍、创作需求、可调参数和版本号，选择 MIT 并确认拥有公开源码与素材的授权后发布。
- 模板详情 `/templates/:id` 展示固定示例、作者、版本、许可和验证状态。作者可下架、重新上架。
- 「原样套用示例」直接创建私有项目，保留源码与来源；无需模型调用。
- 「按参数创建并生成」先保存原版 v1，再由 Agent 基于完整示例源码开发 v2。修改失败可继续使用 v1；未启用 Agent 时该入口禁用，接口也拒绝请求。
- 工作台继续修改需要启用 Agent；不会将社区源码项目重新渲染成内置模板。下载源码包对应当前预览版本。

本地启动：

```bash
npm run dev
# 需要按参数修改和继续开发时：
npm run dev:agent
```

默认启动会初始化两份官方源码示例：打砖块与贪吃蛇。官方标记只能由受信任的初始化代码设置，用户发布接口不能设置。

## 可调参数与需求编译

每个模板最多 6 个参数：

- 整数范围：0–10000，作者指定最小值、最大值、默认值。
- 下拉选项：2–8 个不重复文本选项，默认值必须属于其中之一。

需求中可使用 `{{parameter_id}}` 占位符。所有选择也会以可读文本追加到需求末尾；用户可再补充 500 字以内的创意。后端拒绝未知参数、非法类型、越界取值、未声明占位符及超过 2000 字符的组合需求。前端预览仅辅助展示，后端会重新校验。

例如作者设置「战斗方式」「伙伴数量」「单局时长」，需求说明这些参数如何影响玩法，使用者即可组合自己的选择。当前组合行为来自需求与 Agent 开发，不是固定模块拼装引擎；具体效果仍需试玩。

## 源码快照、署名与权限

每次发布创建新的模板 ID 与独立快照。标题、需求、参数和示例源码发布后不可原地改写；更新时发布一份带新版本号的模板。当前没有模板家族或自动跳转最新版功能。

- 模板不会随着原项目生成、回退或删除而变化；套用得到的项目也不会随模板下架或重新发布而变化。
- 只公开作者确认发布的示例源码及模板内容，不暴露创作者令牌、私有项目 ID、其他版本或原项目对话。
- 作者不能访问其他用户套用后生成的私有项目。
- 下架后匿名和其他用户不能浏览、试玩或新套用；作者可在「我的模板」管理和重新上架。
- 第一阶段只接受 MIT；作者须确认源码、素材具有相应授权，不支持模板私有授权或其他许可切换。
- 副本及后续 Agent 版本保留来源链。单文件 HTML 内保存署名与许可注释，ZIP 另外包含 `ATTRIBUTION.json` 和完整 `LICENSE`。
- 再次发布派生模板会保留已有来源；最多支持 12 层来源，避免无限增长。
- 模板只提供需求与游戏数据，不能配置平台系统提示词、模型端点、命令、密钥或工具权限。

本地支持账号登录和游客身份；云端 M0 使用邮箱账号，但未开放模板发布写入。尚未实现账号找回、人工审核、举报、模板收藏或评论。模板公开后即时可见；官方标记与作者声明不等价于对全部玩法或版权的人工审查。

验证状态由后端计算：有浏览器检查记录的示例标记「示例通过浏览器烟测」，确定性模板版本标记「示例由内置模板生成」，其他示例标记「待试玩确认」。不提供作者自行填写「验证通过」的选项。

## API

接口仍可使用 `/functions/v1/app/api` 前缀，本地 `/api` 为别名。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/templates` | 目录、搜索、筛选和分页；mine 需要鉴权 |
| `GET /api/templates/:id` | 模板元信息、参数、需求及当前是否可使用 Agent |
| `GET /api/templates/:id/play` | 隔离试玩固定示例 |
| `POST /api/projects/:id/templates` | 项目所有者授权发布选定版本 |
| `POST /api/templates/:id/visibility` | 作者上下架，正文 `{ published: boolean }` |
| `POST /api/templates/:id/use` | 创建副本，正文 `{ mode: "copy" }` 或 `{ mode: "customize", values: {...}, extraPrompt: "..." }` |

目录支持 q、kind（official/community）、mine、limit 和 offset 查询参数。

原样套用返回 `201 { project, version }`；按参数生成正常返回 `202 { project, version, task }`。如果副本已保存但 Agent 入队失败，返回 `201` 和 warning，工作台提示重试，避免客户端误认为副本未创建而重复请求。

## 存储与云端适配

本地 `data/db.json` 增加 `creationTemplates` 数组，缺少此字段的旧数据自动兼容。副本创建以一次原子文件替换保存项目、初始版本与来源消息；API 仍要求一个文件数据库仅由一个服务实例使用。

Supabase 适配层与新建数据库 schema 已补齐。现有部署的迁移草案为 `infra/migrations/20261109_community_templates.sql`，包含新表和项目、版本的来源字段。需部署管理员按平台实际支持的迁移机制审阅执行；本次不执行远端 SQL。云端副本创建使用补偿删除处理部分失败，不具备本地单文件提交的原子事务保证。

本机 Agent Worker 不会随 Edge Function 源码自动部署。云端未接 Worker 时，只支持发布、浏览和原样套用；参数生成入口明确不可用。官方示例的本地初始化也不等同于已给云端导入示例。

## 验证边界

类型检查、前端构建和 30 项自动化测试通过。自动化验证使用受控本机 HTTP Agent、独立 Worker 与真实系统 Chrome。双会话浏览器覆盖作者发布、另一用户搜索与试玩、选择参数、源码继承、生成新版本、下载、刷新、上下架与副本独立性。后端测试覆盖参数、授权、越权版本、敏感字段、伪造官方标记、来源与许可导出、持久化。

本轮真实 Qoder 模板联调被自动审批拒绝，理由是需要明确允许向外部服务发送示例源码。因此本轮未向 Qoder 发送游戏源码；受控网关通过不等价于真实模型的生成质量验证。


可审阅的真实 Qoder 联调脚本为 `dev/template-agent-smoke.ts`。它只使用临时数据库与内置贪吃蛇示例，并在发送前要求显式提供 `--allow-external-source`；本轮仅准备脚本，未执行外部联调。该脚本也不属于 `npm test` 的执行范围。
