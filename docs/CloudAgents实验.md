# Cloud Agents 新路线实验

日期：2026-11-10。分支：`experiment/cloud-agents-route`，从 `main` 的 `94ae4c3` 创建。

本轮实现的验证目标：Sites Function 以应用邮箱身份提交一次需求，Cloud Agents Managed Session 异步运行，页面关闭后重新读取同一任务，并保存候选 HTML。不是完整 M1：未实现多文件工程构建、自动 Chrome 玩法验收、社区发布、持续对话或从候选版本继续修改。

## 隔离与当前证据

- 原 M0 队列、路由和本地 Agent 保留。新端点为 `/api/qca/*`，新页面为 `/experiments/qca`，新表为 `myol_qca_jobs`。
- 云端入口只有 `APP_QCA_EXPERIMENT_ENABLED=true` 时才装配实验路由；默认关闭。未设置时新端点返回 404，导航不显示。
- 本轮没有启用站点 `qoder` 能力、创建 PAT、执行远端迁移、发布实验代码或修改线上访问范围。只读状态显示原站点目前为 selected，保留用户当前设置。
- 实际平台上下文确认 Cloud Agents 来源为 `https://api.qoder.com.cn`；代码复制该服务端来源，不从 URL、浏览器配置或站点域名推导。
- 完整回归 `npm test` 共 42 项全部通过，定向 6 项通过；类型检查、前端构建及函数包静态检查通过。
- 定向测试使用受控 API 和 SDK 契约替身，真实 HTTPS Chrome 验证一次提交、关闭页面、恢复结果和隔离试玩；明确显示“本地受控接口演示，不调用真实模型”。这些证据不能证明真实模型生成能力或远端 Provider 的条件更新语义。

## 本地可运行测试

```bash
npm run test:qca
npm run dev:qca-lab
```

实验运行器默认地址 `https://127.0.0.1:8790/account`，使用本机临时自签名证书；仅在本机确认测试证书。注册任意合成邮箱和测试密码，进入“新路线实验”。所有账号和任务只保存在内存，停止服务即消失，不读取线上凭据或 `data/db.json`。

该运行器是受控演示，使用 `tests/helpers/m0-db.ts` 的数据库契约替身和 `dev/qca-fixture.ts`，不进入函数上传目录。不要将它部署为公网应用，也不要输入真实账号密码。

## 实际执行协议

1. 通过现有应用 Cookie 验证用户。POST 创建任务要求 UUID 幂等键，相同用户、同键、同需求恢复同一行。
2. 每个任务分别创建 Agent（无工具）、独立 Environment 和 Session，Agent 引用固定版本，Session 的总预算配置为 10 credits。每天每账号最多创建 3 个实验任务；此预算不代表所有资源的总费用承诺。
3. 创建前向 Models API 验证服务端固定模型是否启用；不接受浏览器指定模型、上游地址、工具或预算，不自动替换模型。
4. 一次 POST 最多执行一个上游副作用。每一步先用行版本和状态 CAS 占用创建意图，只有赢家发请求。页面收到明确成功才提交下一阶段；失败或结果未知立即停止。
5. 最后发送一次 user.message，保存受理事件 ID 后显示“云端运行中”。之后的轮询只读取事件和状态，不发送新消息。
6. POST refresh 完整读取最多 10 页最终 agent.message，保存原始候选文本；只展示文本内容，不暴露工具输出、内部思考、上游资源 ID 或凭据。Session 为 idle 且存在最终消息才确认结果完成。
7. 结果在后续请求读取时归档到本应用数据库；没有永久后台归档进程或 Webhook。网页关闭后由 Cloud Agents 执行，重新进入后查询并归档；长期无人访问时依赖上游会话结果保留策略。
8. 取消操作先请求云端取消，再等待状态确认，不把 HTTP 202 当作已停止。候选 HTML 仅经用户点击后在无同源权限、禁止网络的 iframe 中运行，标记“未验收”。源码下载为文本，不能据此标记玩法成功。

每个任务都创建独立 Environment，避免不同用户共享可写环境；Agent 也按任务独立创建，便于实验隔离，代价是资源开销较大。正式版本应在真实验收后再设计安全的只读模板复用。

## 不确定结果与故障边界

- 创建意图是永久记录，不使用进程内锁，不存在锁超时后自动重发。如果进程在占用后、发请求前退出，任务会停在待确认状态；这是安全停止，不是自动恢复成功。
- 显式 reconcile 按服务器写入的作用域、任务和资源角色元数据扫描云端资源。完整扫描得到唯一匹配才补全映射；空结果保持待确认，多重匹配报冲突。分页未完成不作“不存在”判断。
- 派发结果未知时没有稳定的消息关联契约可证明是否送达，因此不按相同文本猜测，不自动重发；需要人工核对。此限制意味着实验还没有自动恢复所有故障的能力。
- 所有受保护写入都带任务 owner_id、revision、state 条件，状态和资源映射在同一行保存。没有跨表事务、过期租约接管或外部副作用的恰好一次承诺。
- 创建资源成功但本地保存响应丢失后，保留旧意图并通过读取核对。重试 GET 或重新打开页面不会分配新资源。
- 过期／取消／失败任务对应的云端 Agent、Environment、Session 当前不会自动删除；真实试验后应审阅并清理本轮资源，不能默认删除用户其他会话。

## 真实联调前置条件

1. 用户明确选择测试部署目标；不能仅因创建 Git 分支就覆盖现有站点。
2. 开启目标站点 qoder 后端前，必须披露并获得确认：平台会为账号自动创建 Qoder PAT，安全配置到该站点后端 `QODER_PAT`，用于站点调用 Cloud Agents。不在聊天中索要 PAT，不把它写入普通 Secret、前端、Session 环境或源码。
3. 使用 function_backend，在目标测试站点应用 `infra/migrations/20261110_qca_experiment.sql`，不把密码、会话或任务表授予浏览器公共读写权限。
4. 通过支持的设置启用 `APP_QCA_EXPERIMENT_ENABLED=true`，配置实际启用的 `APP_QCA_MODEL`；在 prepare_site 中声明这两个应用配置名，绝不声明平台管理的 QODER_PAT。
5. 部署后使用真实邮箱登录执行一条合成需求，确认 Cloud Agents 接受、完成、保存候选，关闭页面后仍能恢复；验收截图／日志不能包含凭据。平台 BOT_DETECTED 不能通过伪造浏览器身份等方式绕过。
6. 若另建测试站点，应更新服务端固定来源和实验 SCOPE，隔离站点与环境的资源元数据；不要把原生产配置和身份绑定直接复制为另一个目标的已验证事实。

官方接口依据：发送事件会异步触发执行；取消仅表示受理，需要等到 idle。版本、预算、事件格式和模型启用状态按当前官方接口核对，但本分支尚未实际调用真实 Cloud Agents。
